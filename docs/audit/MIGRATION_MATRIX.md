## 1. Classification Guidelines

Every significant component in the `simply1git/simplyytr` repository has been evaluated against the frozen SIMPLYYTR 2.0 system specification and categorized into one of six migration classifications:

- **`KEEP`**: Proven, compliant code ready for direct inclusion with minimal adjustments.
- **`REFACTOR`**: Sound conceptual architecture or integration patterns requiring substantial restructuring, typing, or modernization to meet 2.0 standards.
- **`ADAPT`**: Useful logic, schemas, or prompt templates that must be ported to a different language, layer, or provider interface (e.g., ported from TypeScript to Python/FastAPI, or converted into a pluggable adapter).
- **`REPLACE`**: Capability required by SIMPLYYTR 2.0 but whose legacy implementation is defective, simulated, unmaintained, or architecturally incompatible.
- **`DELETE`**: Unsafe, policy-violating, obsolete, duplicate, or abandoned components that present security, legal, or maintenance liabilities.
- **`UNKNOWN`**: Components whose viability cannot be confirmed without runtime credentials, live services, or user policy clarification.
